The story you are telling

Collections today is a stack of disconnected tools — a dialer here, a strategy spreadsheet there, a compliance team manually checking everything after the fact, and a CRO who has no way to know if last month's strategy change actually helped. This platform replaces that with one orchestrator: every customer journey is a workflow, every decision is logged and explainable, every action is gated by policy at the millisecond it's taken, and every stakeholder gets a surface that answers their first ten questions without scrolling.

The arc: open with a portfolio-wide view → drill into one customer's story → show the AI making decisions you can audit → show compliance blocking an action live → show the risk model + A/B framework that makes this defensible → show the lakehouse and lineage that makes it analyzable → show the runtime that makes it operable → leave them with the 12-week roadmap.

Pre-flight checklist · 10 minutes before

Stack health

  1. Backend is up. Run curl -s http://localhost:8000/api/health — expect {"status":"ok"}.
  2. Frontend is up. Open http://localhost:5173 in your browser. Each page should load without an error banner.
  3. Traffic is flowing. The Operations Floor pulse strip should show non-zero events/min after 30 seconds. If it's flat, the traffic generator died — restart with uv run python -m scripts.run_services.
  4. AI agents have fired. The AI Explorer page should have at least 3 reasoning traces visible. If it's empty, give it 60 more seconds (traffic generator gradually escalates intents).

Browser setup

  1. Window size: maximize, or at minimum 1440 × 900. The dashboards are dense by design.
  2. Zoom: 100% (Cmd-0). Not 110%, not 90% — the layout assumes 100%.
  3. Two tabs prepared: Tab 1 on Operations Floor (your opening), Tab 2 on Customer Story for CUST-0032 (your first drill-in).
  4. Close DevTools. Close other browser windows. Mirror your screen if presenting.

Talk-track props

  1. Have this script open on a phone or second monitor — don't read it word-for-word, but use it for stop boundaries.
  2. Have docs/platform-brief.html ready to leave behind.
  3. One sentence answer ready for "how long would this take to build for us?" → 12 weeks to first stakeholder demo, 6 months to production-grade.

AI Explorer — governable AI
2.5 min
Audience
CROCCOThe "is your AI safe?" question, answered with evidence
Navigate to
AI Explorer → top of the page (decision feed)
What to do
Show the live decision feed; click into one decision to expand reasoning.
Say
"Every AI agent in this platform is governable — meaning every single decision is a structured record with the inputs that went in, the reasoning text from the model, the action it chose, a confidence number, and whether it was escalated to a human. The agents can't take a free-form action. They have to invoke a tool we've defined — record_decision, escalate, request_review, and so on. Every tool call is logged. If a regulator asks 'why did your AI do this?' — you can show them exactly what the model saw and exactly what it decided. This is not a chatbot. This is governed decisioning."
Show
  • Live decision feed — recent AI decisions across all 5 agent types.
  • Click into one decision — show input context, the model's reasoning text, the action chosen, the confidence.
  • Agent type breakdown — digital channel agent, quality reviewer, dispute triage, settlement negotiator, etc.
  • Escalation rate panel — show that some % of decisions get escalated to humans. That's by design — AI knows what it doesn't know.
  • Tokens used + latency per decision — observable cost.
Anticipated questions
Which model is this? GPT? Claude?
"Anthropic's Claude. Same family the platform-level prompts assume. The model identity is captured in every reasoning trace — if we swap models, you'll see when and why."
How do you prevent prompt injection?
"Agents never see raw customer-provided text in the system prompt. We extract structured fields, validate them, and pass them as tool inputs. The agent's output is also constrained to tool calls — it can't say 'transfer money' as freeform text. The combination kills the vast majority of injection vectors."
Are you using RAG?
"For policy lookups, yes — but the source documents are versioned and read-only. The agents can't write to the knowledge base. Every retrieval is logged with the document version, so you can reproduce any decision."

Can my compliance team see this without a developer?
"They get the Compliance landing page — same data, no JSON, no Rego. They see: blocked actions in the last 24 hours, by rule, by reason. And they can drill into any one. We've built it as the surface they'd use day one."

"Add another policy module. The architecture supports it — Rego files are namespaced by regulation. We've shown Reg F; you'd add UDAAP, FCRA, state laws, internal policies, whatever applies. They compose."

What if the model degrades?
"You'd see it in this dashboard — drift in the feature distributions, drift in the prediction distribution, declining AUC on labeled outcomes. We'd also automate alerting on those signals; that's a Horizon-2 item on the roadmap."

What to do
Show the medallion (Bronze/Silver/Gold) layout. Pick one event_id and walk it through all 6 tiers.

Six tiers, one event, full lineage. Watch this — I'm going to paste in one event ID, and the lineage panel will trace it through every tier with timestamps. (Paste an event_id from a recent decision.) Bronze caught it 200ms after Kafka. Silver compacted it in the next batch. Gold's customer_360 mart has it rolled up. Postgres has the projected row. Redis has the published pulse update. This is what governable means at the data layer."
Show
  • Medallion overview — Bronze row count, Silver row count, Gold mart count.
  • Lineage panel — paste an event_id, get the 6-tier walk with timestamps.
  • DuckDB query box — run a quick SELECT on the silver layer to show real Parquet behind it.
  • S3 bucket names visible (in your real AWS account).
Anticipated questions
Why six tiers? Isn't that a lot?
"Each tier serves a different consumer at a different latency. Redis for sub-second UI. Postgres for application reads. Gold marts for BI. Silver Parquet for ad-hoc analytics. Bronze for replay. Kafka for streaming. We don't manually replicate — every tier is computed from the one upstream, so the data is consistent by construction."
Cost?
"S3 storage is cheap — sub-cent per GB-month. The compute to compact Bronze→Silver runs on a schedule and is negligible at this scale. For your bank's volume, total lakehouse cost would be a few hundred a month. Cost dashboard on Risk & ML page shows current spend."

Appendix

If something breaks mid-demo

SymptomQuick recovery
Page won't load The frontend dev server died. Open a terminal, cd web && pnpm dev. Buy time by walking back to your last working page.
Pulse strip shows zeros Traffic generator stopped. uv run python -m scripts.run_services. Tell them: "let me restart the synthetic traffic — give it 30 sec." Move to a static page (Risk & ML model card).
AI Explorer is empty AI agents haven't fired yet. Drive synthetic events with a scenario: uv run python -m scripts.demo cross_channel. Buy 30 sec by walking through the static lakehouse architecture diagram.
An OPA rule blocks something you didn't expect "That's actually the platform doing exactly what we want — refusing an action because of policy. Let me show you why." Open the compliance event and walk through the rule citation. Turn the problem into a feature.
Audience asks about a competitor "Happy to compare in detail offline. Today let me focus on what's in front of you — every capability you're seeing is in your codebase, not behind a vendor wall." Move on.

Phrases to use

  • "Every decision is a structured record" — when talking AI.
  • "Policy at the millisecond the action is taken" — when talking compliance.
  • "Six tiers, one event, full lineage" — when talking lakehouse.
  • "Statistical significance, not 'felt better'" — when talking risk.
  • "This is not a chatbot — this is governed decisioning" — when AI comes up.

Phrases to avoid

  • "It's just a POC" — undersells the real engineering. Say "the reference implementation."
  • "Should work" — sounds uncertain. Demo what's in front of you; if something fails, see the table above.
  • "We could add…" — overpromises. Say "the architecture supports it; we'd estimate a sprint to add."
  • "Magic happens" — never say magic. Always explain.
